## Required implementation

### 1. Atlas test package boundary

Create a private package at `kanji-atlas/package.json`.

- `private: true`.
- Declare a supported Node engine range that includes Claude's Node 22 and Codex's Node 24.
- Pin Playwright to the exact version actually used for all submitted evidence; do not use `^`, `~`, `latest`, or an unbounded range.
- Commit a lockfile generated by npm for that exact dependency graph.
- Add scripts with clear names for:
  - installing the required Chromium binary;
  - core gates;
  - browser gates;
  - full release gates: core first, then browser.
- Do not duplicate native-wrapper dependencies or modify `native/package.json`.
- `kanji-atlas/.gitignore` must exclude at least `node_modules/`, Playwright test output/report directories, logs, and common local OS artifacts without hiding package or lock files.

### 2. One owned local HTTP server

`run-browser-gates.mjs` must start one Node-built-in HTTP server for the Atlas root.

- Bind only to `127.0.0.1`.
- Request port `0` and use the OS-assigned port; no fixed port.
- Serve only files inside the Atlas root.
- Decode and normalize request paths safely; traversal, malformed encoding, directory escape, and unsupported methods must not expose files outside Atlas.
- Provide appropriate responses for `/` and `/index.html` and sufficient MIME types for the app assets used by these tests.
- Wait for the server to be listening before starting tests.
- Pass the resolved `http://127.0.0.1:<port>/index.html` through `SMOKE_URL` to every child.
- Close the server in every success, failure, timeout, signal, and internal-error path.
- Do not invoke Python or another external server tool.

### 3. Browser-test portability

For all three smoke files:

- remove Claude-only absolute paths and fixed ports;
- remove ownership of HTTP server processes;
- consume and validate `SMOKE_URL` supplied by the runner;
- keep the existing user-flow assertions and their meaning intact;
- use `try/finally` or an equivalent structure so browser/context/page resources close after success or failure;
- return a deterministic non-zero exit for assertion failures, navigation failures, missing configuration, or uncaught errors;
- do not silently catch a failed assertion or change selectors merely to make the current product pass.

Direct invocation without `SMOKE_URL` may fail with a concise configuration message. The supported normal entry point is the browser runner.

### 4. Deterministic runner supervision

- Use only Node built-ins in the runner itself.
- Resolve paths from the runner's own location.
- Spawn tests with `process.execPath`, `shell: false`, and the controlled environment.
- Run all three tests serially and continue after an ordinary test failure.
- Capture per-test exit/signal, duration, stdout, and stderr.
- Apply a documented per-test timeout that accommodates the measured recognition test while still terminating hangs.
- On timeout, terminate the child and escalate to a hard kill after a short grace period.
- A child failure, signal, timeout, spawn error, missing file, server error, dirty start, or repository mutation must make the runner exit non-zero.
- Apply the same read-only clean-start and before/after Git-status principles as Batch B. Never reset, restore, clean, or stash user work.
- Default output must be concise and human-readable; `--json` must emit one valid JSON document to stdout.
- Support `--help`; reject unknown arguments.
- The runner may accept a documented Atlas-path override for relocated-copy proofs.

### 5. Full release entry point

The package's full release script must execute the committed core runner first and invoke the browser runner only if core passes. It must propagate a non-zero result from either tier.

Do not modify `run-core-gates.mjs` to accomplish this.

Report the resolved local URL and port as evidence that the port was dynamically allocated; do not freeze that value as an assertion.

## Required negative proofs

All destructive proofs must use temporary copies/worktrees outside the working repository.

Demonstrate that:

1. an occupied unrelated fixed port does not affect the runner because it uses port `0`;
2. one browser test exiting non-zero is reported, remaining whitelisted tests still run, and the runner exits non-zero;
3. a hanging temporary browser-test fixture times out, is terminated, and leaves no child or server process behind;
4. a temporary test mutation of a tracked file makes the gate fail without automatic restoration;
5. an already dirty temporary worktree is refused before the server or any browser test starts;
6. a traversal request such as an encoded `../` attempt cannot read a known file outside the Atlas root;
7. passing and failing `--json` outputs both parse successfully.

The real project tree must be clean after all proofs.
